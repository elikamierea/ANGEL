# ノードとエッジの編集（基本操作の完全リスト）

> このページは Graph セクションのメイン入口ドキュメントであり、LOD、Auto Layout、範囲選択、ドラッグ、一括変換に関する関連説明も含みます。

## 始める前に：どんなシステムを扱っているのか

ANGEL GUI の Graph は、気軽に四角と線を描くだけのホワイトボードではありません。

これは**長期的な設計の保存のための構造化システム**に近く、プロジェクト内のアイデア、関係、実装の方向性、外部リソース参照を少しずつ保存していくためのものです。

おおまかに次の層として理解できます：

### 1. ノード（Node）

ノードは主に、設計単位または情報単位を記録するために使います。

例えばノードは次を表せます：

- ゲームプレイのアイデア
- システムモジュール
- キャラクターやオブジェクト
- タスクのステップ
- まだ実装が必要な機能ブロック

ノード自体は次のようなテキスト情報を持てます：

- `name`
- `progress`
- `detail`
- `status`

そのため、ノードは単なる図形ブロックではなく、プロジェクトの設計情報の担い手です。

### 2. エッジ（Edge）

エッジは主に、ノード間の関係を表現するために使います。

例えばエッジは次を表せます：

- 依存関係
- 呼び出し関係
- プロセスの順序
- 概念的な関連
- 情報源や影響経路

そのため、エッジは装飾的な線ではなく、Graph における関係セマンティクスの主な担い手です。

### 3. `resourceBindings`

Graph は `resourceBindings` を通じて、ノードを外部ファイルにリンクすることもサポートします。

次のように理解できます：

- このノードがどのコードに対応するか
- この設計項目がどのリソースファイルに関連するか
- この概念が最終的に外部実装のどこに落ちるか

これにより、グラフ内の設計情報は図の中だけにとどまらず、少しずつ実際のプロジェクトファイルと結びつきます。

### 4. なぜこの仕組みなのか

このシステムの目標は、いま理解する助けになるだけではありません。次のためでもあります：

- 設計情報を時間をかけて保存する
- 複雑なプロジェクト内の関係を可視化する
- 将来の自分に役立つ文脈を残す
- agent が現在のプロジェクト状態を理解し、協働を続けやすくする

そのため、使用の観点からは Graph は次に近いものです：

- **設計情報の保存層**
- **関係の表現層**
- **agent との対話と文脈の継承のための中間層**

## 1. ビューとナビゲーション

- **中ボタンドラッグ（MMB）** または **右ボタンドラッグ（RMB）**：ビューをパン
- **マウスホイール**：マウス位置を中心にズーム
- **Reset View ボタン**：デフォルトビューに戻る

## 2. 選択

### 1) シングルクリック選択

- **ノードを左クリック**：単一ノードを選択
- **エッジまたはエッジ端点を左クリック**：エッジを選択
- **Ctrl + ノードを左クリック**：そのノードを現在の複数選択に追加または削除（トグル）
- **空白をクリック**：選択を解除

### 2) 範囲選択

- **Shift + 左ドラッグ**：範囲選択し、現在の選択を置き換える
- **Ctrl + 左ドラッグ**：加算的な範囲選択、ヒットしたノードをトグル
- **Ctrl + Shift + 左ドラッグ**：現在は加算選択と同じ挙動で、Ctrl の経路に従う

注意：範囲選択は **LOD hidden** ノードを含めることをすでにサポートしており、大きなグラフの一括操作でそれらを取りこぼさないようになっています。

## 3. ノードとエッジの作成

- **N + 左ドラッグ**：ノードを作成、ドラッグで初期サイズを決定
- **N + 左クリック**：クリック位置を中心にデフォルトサイズのノードを作成
- **C + 左ドラッグ（ノードから開始）**：エッジを作成
- **M + 左ドラッグ（ノードから開始）**：mirror ノードを作成。名前は `ソース名@ローカル名`、内容はソースから独立（ソースを削除すると、そのミラーも一緒に削除されます）

## 4. 編集と変換

- **ノードをドラッグ**：ノードを移動、複数選択したルートノードは一緒に移動
- **ノードの辺または角のハンドルをドラッグ**：ノードをリサイズ
- **すでに複数選択中で、選択済みノードをヒットした状態で右クリック**：一括変換メニューを開く
  - Stretch
  - Rotate 90
  - Flip Horizontal
  - Layout（現在の選択集合内でのレイアウトをプレビュー）
- **変換プレビューセッション**：
  - `Enter` で適用
  - `Esc` でキャンセル

プロジェクトのグラフがすでに大きくなっているなら、早めに範囲選択と一括変換を覚える価値があります。効率に非常に明確な差が出ます。

## 5. LOD と可視性

システムは各ノードの画面上の面積に基づいて、表示する詳細度を決めます。

単純に次のように理解できます：

- ノードが小さすぎると `hidden` に入ることがある
- 少し大きいノードは簡略化された情報のみ表示
- さらにズームインして初めて、名前やより多くの詳細が徐々に現れる

目的は情報を隠すことではなく、縮小時に大きなグラフを読みやすく保ち、すべてのテキストが一度に視覚的ノイズになるのを避けることです。

そのため、ズームレベルによってノードが異なる詳細度を表示しても、通常はそれが正常な動作です。

## 6. Auto Layout（ELK）

Auto Layout は ELK を使ってノードの配置を自動的に整理します。

次のときに役立ちます：

- グラフが複雑になりすぎて、手作業での配置が快適でなくなった
- 関係グラフを素早くより整った構造に整理したい
- 手動で微調整する前に、読みやすい初期レイアウトが欲しい

よくある推奨は：

- まず局所的な選択で試す
- 結果が許容できそうなら、より広い範囲での使用を検討する

自動レイアウトは通常、まず構造を整理するのに向いていますが、必ずしも望む最終的な視覚配置と一致するとは限りません。

## 7. キーボードショートカット

- `Ctrl+Z` / `Ctrl+Y`：Undo / Redo
- `Ctrl+Shift+Z`：Redo（代替経路）
- `Ctrl+S`：保存
- `Ctrl+N`：新規プロジェクト
- `Ctrl+1..4`：Layer を切り替え（L0..L3）
- `Ctrl+A`：すべてのノードを選択
- `Ctrl+C` / `Ctrl+X` / `Ctrl+V`：コピー / カット / 貼り付けプレビュー
- 貼り付けプレビュー中に `V` を離す：貼り付けを確定
- `Delete` または `D`：現在選択中のノードまたはエッジを削除

## 8. Inspector のよく使う項目

### ノードのよく使うフィールド

- `name`
- `progress`
- `detail`
- `status`
- `color index`

### エッジのよく使うフィールド

- `relation`
- `label`
- `description`
- `path style`
- `stroke style`
- `arrow`

### 包含とミラー

- 包含関係（どのノードがどれを含むか）とミラーはエッジではありません。インスペクターは専用の**包含関係**・**ミラー**パネルで表示し、項目をダブルクリックすると対象ノードへジャンプします。

### リソース参照

- 右側パネルで `resourceBindings` を追加または削除

これは重要です。グラフ内の設計項目が、追跡可能な形で実際に外部ファイルとリンクされているかを決めるからです。
