# 画像生成

> このページは、agent にプロジェクト用の画像を生成してもらう方法と、それと同じくらい大切な「現実的に何を期待してよいか」について説明します。

## 画像生成はワークフローのどこに位置するか

画像生成は通常、**最初にやること**ではありません。より実際的な順序はこうです：

1. まず設計（Graph）を作り、ビジュアルは**プレースホルダー**（placeholder：単色の図形、単純な矩形や円など）で済ませた状態で、agent にゲームプレイとロジックを実装してもらう。
2. そのプレースホルダー版が**コンパイルして動く**ようにし、メカニクスがおおむね正しい状態にする。
3. **その後で初めて**、プレースホルダーを生成画像に置き換え始める。

理由は単純です。ビジュアルは最後に投資すべきものだからです。メカニクスがまだ変わっているうちに何度も画像を作り直すのは無駄になります。

## 「生成 → 組み込む → テスト」のループ

プレースホルダー版がおおむね動くようになったら、画像生成は一発で終わる工程ではなく、**反復的なループ**になります：

1. **生成**——特定の要素（プレイヤー、コイン、敵、背景……）の画像を生成する。
2. **組み込む**——プロジェクトに保存し、コード内でプレースホルダーの代わりに配線する。
3. **実行してデバッグ**——実際にプロジェクトを動かし、**本物のシーン**で・**本物のサイズ**で・**本物の背景**の前で結果を見る。
4. **再生成**——見た結果をもとに依頼を調整し、もう一度生成する。

素材ごとに、たいていこのループを数回まわすことになります。画像を単体で見てもほとんど分かりません。**動いているシーンの中で見て**初めて、それが通用するか分かります。

ANGEL での配線：

- プロジェクト作成時に画像生成つきのテンプレートを選ぶ——**Default（+画像生成）** か **Extended（+画像生成）**——と、プロジェクトに resource-provider という agent が含まれます。(プロジェクトの作成と開く（New/Open/Save）)[project-io.md] を参照。
- 生成された画像は `assets/generated/images/` 以下に保存され、そのパスが agent に返されるので、agent はそれを参照したり、Create Sprite などのツールに渡したりできます。(Create Sprite)[create-sprite.md] を参照。
- 画像生成は現在 OpenAI（API key）の機能です。**設定 → Agent Model** で具体的な画像モデルを選ぶか、auto のままにできます。

## 非常に重要な前提：品質は保証されない

これははっきり言っておく価値があります：

**現在の各社の画像モデルは——例外なく——生成画像をスタイル化された具体的なシーンに完璧に馴染ませられるほどの能力はまだありません。最終的な仕上がりは保証されません。**

実際には、これは次のことを意味します：

- 生成画像は単体では問題なく見えても、シーンに置いた途端にしっくりこないことがあります——スタイルが合わない、比率が合わない、シルエットが合わない、背景の前での色が合わない。
- 多数の素材にわたって**一貫したアートスタイル**を揃えるのは特に難しいです。
- 厳しい制約（正確なポーズ、正確な視点、ピクセル単位で正確なエッジ、きれいな透明切り抜き、「同じキャラだが左を向いた状態」）は、安定して満たされないことが多いです。
- 反復は助けになりますが上限があります。現在のモデルでは、どうしても到達できない見た目があります。

ですので、健全な使い方はこうです：

- 生成アートは、**プレースホルダーから「十分使える」状態へ素早く到達するための手段**として扱い、最終的に出荷できる・スタイルが完璧に揃ったアートを得る手段とは考えない。
- プロンプトでは重要な点（主体、シルエット、配色、背景は透明か単色か）を具体的に書きつつ、一部の要求は通らないと受け入れる。
- **最後の仕上げは自分でやる**覚悟を持つ——手作業のレタッチ、あるいは最重要の素材は手描きのアートに差し替える。
- どの素材が本当にスタイルを揃える必要があるかを見極め、そこに反復を費やす。重要でない素材は粗いままにしておく。

## 実用的な結論

- まずプレースホルダーでメカニクスを正しくする。動いてから画像生成を持ち込む。
- 「生成 → 組み込む → 実行 → 再生成」のループを前提にし、本物のシーンの中で良し悪しを判断する。
- 完璧でスタイルが完全に揃った結果を期待しない——現在のモデルはそれを保証できないので、反復と手作業の最終仕上げを織り込んでおく。
