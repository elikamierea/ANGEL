# Provider の設定

> このページでは、モデル Provider、モデル名、および関連するアクセス認証情報の設定方法を説明します。

## 現在設定できること

モデル設定では、現在設定できる主な項目は次のとおりです：

- Provider タイプ
- リクエスト方式 / Method
- テキストモデル名
- 画像モデル名
- API Key / OAuth（provider による）

## 現在接続されている Provider

現在の GUI はすでに次の Provider に接続済み、または接続準備ができています：

- OpenAI
- Anthropic
- Google
- xAI（Grok）
- DeepSeek

そのうち：

- **OpenAI** は現在 `API Key` と `OAuth` の両方に対応
- **Anthropic / Google / xAI / DeepSeek** は現在主に `API Key` で設定

環境が正常に動作するか手早く確認したいだけなら、最も簡単な方法は通常：

1. Provider を選ぶ
2. モデル名と認証情報を入力する
3. 設定を保存する
4. Agent Chat を開き、できるだけ簡単なメッセージを送って正常に返信されるか確認する

これが「Key が使えるか」を確認する最も直接的な方法です。

## セッションの途中で Provider を切り替えることについて

同じセッションの途中で Provider を切り替えるサポートは、現時点ではまだかなり限定的なので、安定したワークフローとしては推奨しません。

理由は単純です。Provider が異なれば、リクエスト形式、コンテキストの構成方法、レスポンス構造、ツール呼び出しの詳細がまったく同じではありません。UI 上は単に 1 つの会話を続けているように見えても、内部のコンテキストはきれいに引き継げるとは限りません。

そのため、現時点でより安全な推奨は：

- **Provider を切り替えたい場合は、新しいセッションを始めるようにする**
- 同じセッション履歴が異なる Provider 間で完全にスムーズに続くと当然視しない

異なるモデルを軽く試すだけなら、リスクは通常小さいです。しかし、現在のセッションにすでに多くのコンテキスト、ツール呼び出し、画像入力が含まれている場合、途中で Provider を切り替えると挙動の違いが生じやすくなります。

## Humanize：まだ実験的な未完成機能

モデル設定には `Humanize` 関連のスイッチもあります。

その目的は、レスポンスをより自然で、人が話すような感じにし、過度に機械的・テンプレート的にしないことです。

ただし、この部分は今のところ **実験的・未完成の機能** として扱うほうがよいです：

- ときには表現をより自然にする
- ときには不安定なスタイルの変化をもたらすこともある
- まだ完全に成熟した正式機能として扱うべきものではない

出力スタイルを重視するなら、オンとオフを比較してみるとよいでしょう。しかし、今は安定性、予測可能性、トラブルシューティングのしやすさを優先するなら、当面はオフのままにしておくほうが通常はよいです。

## 実用的な提案

初めて Provider を設定する場合、推奨される順序は通常：

1. まず 1 つの Provider を選ぶ
2. モデル名と認証情報を入力する
3. Agent Chat で短いメッセージを送り、動作することを確認する
4. 基本が安定したら、humanize などの追加オプションを有効にするか検討する

こうすることで、「基本的な接続性の問題」と「スタイル関連の機能の問題」を切り分けやすくなります。
