# Quick Start：初回起動後にすること

> ANGEL GUI を初めて使う場合は、以下の順序で最小限の動作確認フローを一度通すことをおすすめします。

## 1. まず Provider / API Key を設定する

最初にモデル関連の設定を開き、使用したい Provider とアクセス認証情報を入力します。

少なくとも次の項目を完了することをおすすめします：

- Provider を選択する
- 呼び出し方法 / Method を確認する
- モデル名を入力する
- 現在の Provider が認証情報を必要とする場合は、API Key または OAuth 情報を入力する

まだ設定したことがない場合は、まずこちらを参照してください：

- (Provider 設定)[provider-setup.md]

## 2. 一度チャットして Key が使えることを確認する

設定が完了したら Agent Chat を開き、できるだけ簡単なテストメッセージを送信します。例：

- `hello`
- `test`
- `こんにちは。接続が正常か確認するために、短く一言返信してください。`

Agent が正常に返信すれば、通常は次のことを意味します：

- Provider の設定がおおむね正しい
- Key / Token が有効である
- 現在のモデルリクエストの経路がつながっている

この段階で既に会話が失敗する場合は、プロジェクトのフローに進む前に、まず Provider の設定を見直すことをおすすめします。

## 3. Default プロジェクトを新規作成する

次に **File → New Project** で新しいプロジェクトを作成し、次を選択します：

- `Default`

これにより、まず最小のテンプレートでローカルのプロジェクトフローが正常かを確認できます。

作成後、プロジェクトが正常に開き、デフォルトの内容と基本的な UI が表示されることを確認してください。

プロジェクト作成のフローにまだ慣れていない場合は、続けてこちらを参照してください：

- (プロジェクトの作成と開く（New/Open/Save）)[project-io.md]

## 4. プロジェクトを一度コンパイルして環境を確認する

プロジェクトの作成後、**Execute** メニューでコンパイルを一度実行します。

まず最も基本的なステップから始めることをおすすめします：

- Compile

コンパイルが成功すれば、通常は次のことを意味します：

- ローカルのプロジェクトテンプレートが使用可能である
- コンパイルの経路が使用可能である
- 現在のプロジェクト環境がおおむね健全である

必要に応じて、続けて次も試せます：

- Run
- Test

関連する詳細は次を参照してください：

- (実行と起動（Compile/Run/Test）)[execute.md]

## 5. ここまで問題なければ、通常どおり使い始められます

以下の項目がすべて通れば、通常は環境が使える状態に十分整っています：

- Provider / API Key の設定が完了している
- Agent Chat で正常に会話できる
- `Default` プロジェクトを正常に作成できる
- プロジェクトを正常にコンパイルできる

これらがすべて正常なら、グラフ編集、Agent、リソースツール、その他の機能へ進めます。
