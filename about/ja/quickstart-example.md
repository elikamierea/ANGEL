# 使用例

> このページでは、ANGEL GUI をゼロから試すための最小の例フローを示します。目標は、最初からグラフを非常に複雑にすることではなく、まず一通りの体験をしてもらうことです：プロジェクトを作る → 設計グラフを作る → agent に実装してもらう → コンパイルして実行する。

## 目標

とても小さなサンプルプロジェクトを作ります：

- プレイヤーがシーンの中央に出現する
- プレイヤーは移動と旋回ができる
- シーンにコインと敵が出現する
- プレイヤーはコインを集めてスコアを得る
- 敵がプレイヤーに触れるとプレイヤーが消える
- プレイヤーが消えたあと、敵が画面外へ出て、その後プレイヤーが再び出現する

## ステップ 1：`Default` の新規プロジェクトを作る

まず使います：

- **File → New Project**

新しいプロジェクトを作成し、次を選びます：

- `Default`

これにより最初から余計な構造を持ち込まずに済むので、初回の試用に向いています。

## ステップ 2：メインノード `シーン` を作る

Graph に入ったら、ノードを 1 つ作成し、次の名前を付けます：

- `シーン`

次の内容を入力します：

```text
ウィンドウサイズは960*540。最初、プレイヤーは画面中央にいる。

シーンにコインが出現し、プレイヤーはそれを集めてスコアを上げられる。

シーンに敵が出現し、プレイヤーに触れるとゲームが終了する。

1秒ごとにチェックする。コインが無ければ、画面内のランダムな位置にコインを1個生成する。コインの数が3未満なら、20%の確率でコインを1個生成する。

プレイヤーがコインを3個集めるごとに、画面外のランダムな位置に敵を1体生成する。生成ルール：中心から始め、0〜360度の範囲で一様乱数の角度を選び、その方向の外向きの線上で、ウィンドウ境界から少なくとも100ピクセル離れた最も近い点を選ぶ。

敵がプレイヤーに触れると、プレイヤーが消える。プレイヤーが消えたあと、敵は画面外へ出ようとする。すべての敵が画面外へ出たら、プレイヤーを再び生成する。
```

このノードは、ゲームプレイサンプル全体のマスターシーンルールセットとして理解できます。

## ステップ 3：その内部に 3 つの子ノードを作る

次に、`シーン` ノードの内部に 3 つのノードを作成します：

- `プレイヤー`
- `コイン`
- `敵`

### ノード：プレイヤー

次の内容を入力します：

```text
プレイヤーを表す白い二等辺三角形を描く。底辺の幅は24ピクセル、高さは32ピクセル。

プレイヤーはA/Dキーで毎秒180度回転する。Wを押し続けると毎秒300ピクセルで前進する。Sを押し続けると毎秒100ピクセルで後退する。
```

### ノード：コイン

次の内容を入力します：

```text
見た目：半径8ピクセルの黄色い円
```

### ノード：敵

次の内容を入力します：

```text
見た目：赤い長方形

速度は毎秒100〜200の間で、プレイヤーに向かって移動する。プレイヤーが存在しない場合は、最も近い境界に向かって画面外へ移動する。

幅と高さは16〜40ピクセルの間。

これら3つの値は生成時にランダム化され、その後は固定される。
```

## ステップ 4：エッジの関係を作る

ノードを作成したら、2 本の関係エッジを追加します。

### エッジ：敵 → プレイヤー

relation を次に設定します：

- `destroys`

次の内容を入力します：

```text
敵がプレイヤーに触れると、プレイヤーが消える。
```

### エッジ：プレイヤー → コイン

relation を次に設定します：

- `collects`

次の内容を入力します：

```text
プレイヤーがコインに触れると、コインが集められる。
```

ここまでで、最小ながら完全な設計構造ができています：

- マスターシーンのルールセット
- オブジェクトノード
- それらのオブジェクト間の関係

これだけで、agent の実装テストとして使うのに十分です。

## ステップ 5：programmer エージェントに実装してもらう

上記のノードとエッジがすべて整ったら、**programmer** に切り替えて、こう言います：

```text
こんにちは、このソフトを試しています。サンプルプロジェクトを用意しました。実装してください。
```

このステップの目的は、programmer エージェントに、いま作成した Graph 構造をコードに変換させてみることです。

## ステップ 6：結果を待つ

メッセージを送ったら、programmer エージェントの応答を待ちます。

このステップはすぐに終わるとは限りません。次のことが必要になる場合があるからです：

- 現在の Graph 構造を読む
- ノードとエッジが表現するルールを理解する
- コードをどこに落とすか整理する
- プロジェクトファイルへ少しずつ書き込む

そのため、ここでのポイントは：

- まず一巡の実装を完了させる
- 与えた設計構造を正しく理解できるか観察する

## ステップ 7：Execute でコンパイルして実行する

programmer エージェントが終わったら、上部メニューを使います：

- **Execute**

まず実行します：

- **Compile Project**

コンパイルが成功したら、続けて：

- **Run Project**

この時点で、一通りの試用を完了したことになります：

- Graph で設計を書く
- agent でその設計を読んで実装する
- Execute で結果をコンパイルして実行する

これがこのチュートリアルの到達点です。

## この例で検証したいこと

このフロー全体が動けば、通常は次を意味します：

- 基本的なプロジェクトの作り方が分かった
- ノードとエッジで設計を表現する方法が分かった
- programmer エージェントがその設計構造を読んで利用できる
- ローカルのコンパイルと実行のパイプラインが基本的に動いている

言い換えると、この例をスムーズに完了できれば、ANGEL GUI のコアワークフローの最初の一通りの体験をすでに終えたことになります。
