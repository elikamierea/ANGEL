# 노드와 엣지 편집（기본 조작 전체 목록）

> 이 페이지는 Graph 섹션의 주요 진입 문서이며, LOD, Auto Layout, 범위 선택, 드래그, 일괄 변환에 관한 관련 설명도 포함합니다.

## 시작하기 전에：어떤 시스템을 다루는가

ANGEL GUI 의 Graph 는 그저 박스와 선을 자유롭게 그리는 화이트보드가 아닙니다.

이는 **장기적인 설계 보존을 위한 구조화 시스템**에 더 가깝고, 프로젝트 안의 아이디어, 관계, 구현 방향, 외부 리소스 참조를 점차 보존하는 데 사용됩니다.

대략 다음 계층으로 이해할 수 있습니다：

### 1. 노드（Node）

노드는 주로 하나의 설계 단위 또는 정보 단위를 기록하는 데 사용됩니다.

예를 들어 노드는 다음을 나타낼 수 있습니다：

- 게임플레이 아이디어
- 시스템 모듈
- 캐릭터나 오브젝트
- 작업 단계
- 아직 구현이 필요한 기능 블록

노드 자체는 다음과 같은 텍스트 정보를 담을 수 있습니다：

- `name`
- `synopsis`
- `detail`
- `status`

따라서 노드는 단순한 그래픽 블록이 아니라, 프로젝트 설계 정보의 담지체입니다.

### 2. 엣지（Edge）

엣지는 주로 노드 간의 관계를 표현하는 데 사용됩니다.

예를 들어 엣지는 다음을 나타낼 수 있습니다：

- 의존 관계
- 호출 관계
- 프로세스 순서
- 개념적 연관
- 정보 출처나 영향 경로

따라서 엣지는 장식용 선이 아니라, Graph 에서 관계 의미론의 주요 담지체입니다.

### 3. `resourceBindings`

Graph 는 `resourceBindings` 를 통해 노드를 외부 파일에 연결하는 것도 지원합니다.

다음과 같이 이해할 수 있습니다：

- 이 노드가 어떤 코드에 대응하는지
- 이 설계 항목이 어떤 리소스 파일과 연관되는지
- 이 개념이 최종적으로 외부 구현의 어디에 떨어지는지

이로써 그래프 내 설계 정보가 도면 안에만 머무르지 않고, 점차 실제 프로젝트 파일과 연결됩니다.

### 4. 왜 이렇게 작동하는가

이 시스템의 목표는 지금 이해를 돕는 것만이 아닙니다. 다음을 위한 것이기도 합니다：

- 설계 정보를 시간에 걸쳐 보존
- 복잡한 프로젝트 내 관계를 시각화
- 미래의 자신에게 유용한 맥락을 남김
- agent 가 현재 프로젝트 상태를 이해하고 협업을 이어가기 쉽게 함

따라서 사용 관점에서 Graph 는 다음에 더 가깝습니다：

- **설계 정보 저장 계층**
- **관계 표현 계층**
- **agent 와의 소통 및 맥락 계승을 위한 중간 계층**

## 1. 뷰와 내비게이션

- **가운데 버튼 드래그（MMB）** 또는 **오른쪽 버튼 드래그（RMB）**：뷰 이동（Pan）
- **마우스 휠**：마우스 위치를 중심으로 확대/축소
- **Reset View 버튼**：기본 뷰로 복귀

## 2. 선택

### 1) 단일 클릭 선택

- **노드를 왼쪽 클릭**：단일 노드 선택
- **엣지 또는 엣지 끝점을 왼쪽 클릭**：엣지 선택
- **Ctrl + 노드 왼쪽 클릭**：그 노드를 현재 다중 선택에 추가하거나 제거（토글）
- **빈 공간 클릭**：선택 해제

### 2) 범위 선택

- **Shift + 왼쪽 드래그**：범위 선택, 현재 선택을 대체
- **Ctrl + 왼쪽 드래그**：가산 범위 선택, 맞은 노드를 토글
- **Ctrl + Shift + 왼쪽 드래그**：현재는 가산 선택과 동일하게 동작하며, Ctrl 경로를 따름

참고：범위 선택은 이미 **LOD hidden** 노드를 포함하는 것을 지원하여, 큰 그래프의 일괄 작업에서 그것들을 놓치지 않도록 합니다.

## 3. 노드와 엣지 생성

- **N + 왼쪽 드래그**：노드 생성, 드래그로 초기 크기 결정
- **N + 왼쪽 클릭**：클릭 위치를 중심으로 기본 크기 노드 생성
- **C + 왼쪽 드래그（노드에서 시작）**：엣지 생성
- **M + 왼쪽 드래그（노드에서 시작）**：mirror 노드 생성

## 4. 편집과 변환

- **노드 드래그**：노드 이동, 다중 선택된 루트 노드는 함께 이동
- **노드 변이나 모서리 핸들 드래그**：노드 크기 조정（Resize）
- **이미 다중 선택된 상태에서 선택된 노드를 맞춰 오른쪽 클릭**：일괄 변환 메뉴 열기
  - Stretch
  - Rotate 90
  - Flip Horizontal
  - Layout（현재 선택 집합 내 레이아웃 미리보기）
- **변환 미리보기 세션**：
  - `Enter` 로 적용
  - `Esc` 로 취소

프로젝트 그래프가 이미 커지고 있다면, 일찍 범위 선택과 일괄 변환을 익혀 둘 가치가 있습니다. 효율에서 매우 뚜렷한 차이가 납니다.

## 5. LOD 와 가시성

시스템은 각 노드의 화면상 면적에 따라 표시할 디테일 정도를 결정합니다.

단순히 다음과 같이 이해할 수 있습니다：

- 노드가 너무 작으면 `hidden` 에 들어갈 수 있음
- 조금 더 큰 노드는 단순화된 정보만 표시
- 더 확대해야 비로소 이름과 더 많은 디테일이 점차 나타남

목적은 정보를 숨기는 것이 아니라, 축소했을 때 큰 그래프를 읽기 쉽게 유지하여 모든 텍스트가 한꺼번에 시각적 잡음이 되는 것을 피하는 것입니다.

따라서 확대 수준에 따라 노드가 서로 다른 디테일 정도를 표시해도, 보통은 정상 동작입니다.

## 6. Auto Layout（ELK）

Auto Layout 은 ELK 를 사용해 노드 배치를 자동으로 정리합니다.

다음과 같을 때 유용합니다：

- 그래프가 너무 복잡해져 손으로 배치하기 불편해짐
- 관계 그래프를 빠르게 더 정돈된 구조로 정리하고 싶음
- 수동 미세 조정 전에 읽기 쉬운 초기 레이아웃을 원함

흔한 권장 사항은：

- 먼저 국소 선택에서 시도해 보기
- 결과가 받아들일 만하면 더 넓은 영역에서 사용 고려

자동 레이아웃은 보통 먼저 구조를 정리하는 데 좋지만, 항상 원하는 최종 시각 배치와 일치하지는 않습니다.

## 7. 키보드 단축키

- `Ctrl+Z` / `Ctrl+Y`：Undo / Redo
- `Ctrl+Shift+Z`：Redo（대체 경로）
- `Ctrl+S`：저장
- `Ctrl+N`：새 프로젝트
- `Ctrl+1..4`：Layer 전환（L0..L3）
- `Ctrl+A`：모든 노드 선택
- `Ctrl+C` / `Ctrl+X` / `Ctrl+V`：복사 / 잘라내기 / 붙여넣기 미리보기
- 붙여넣기 미리보기 중 `V` 떼기：붙여넣기 확정
- `Delete` 또는 `D`：현재 선택된 노드나 엣지 삭제

## 8. Inspector 자주 쓰는 항목

### 노드 자주 쓰는 필드

- `name`
- `synopsis`
- `detail`
- `status`
- `color index`

### 엣지 자주 쓰는 필드

- `relation`
- `label`
- `description`
- `path style`
- `stroke style`
- `arrow`

### 리소스 참조

- 오른쪽 패널에서 `resourceBindings` 추가/제거

이 단계는 중요합니다. 그래프 내 설계 항목이 추적 가능한 형태로 실제로 외부 파일과 연결되는지를 결정하기 때문입니다.
