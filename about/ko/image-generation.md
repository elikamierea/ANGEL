# 이미지 생성

> 이 페이지는 agent 에게 프로젝트용 이미지를 생성하게 하는 방법과, 그에 못지않게 중요한 "현실적으로 무엇을 기대할 수 있는가"에 대해 설명합니다.

## 이미지 생성은 워크플로의 어디에 위치하는가

이미지 생성은 보통 **가장 먼저 하는 일이 아닙니다**. 더 실용적인 순서는 다음과 같습니다：

1. 먼저 설계(Graph)를 만들고, 비주얼은 **플레이스홀더**(placeholder：단색 도형, 단순한 사각형/원 등)로 둔 채 agent 에게 게임플레이와 로직을 구현하게 합니다.
2. 그 플레이스홀더 기반 빌드가 **컴파일되고 실행되도록** 하여, 메커니즘이 대체로 맞게 합니다.
3. **그 다음에야** 플레이스홀더를 생성 이미지로 교체하기 시작합니다.

이유는 단순합니다. 비주얼은 가장 마지막에 투자할 가치가 있는 부분이기 때문입니다. 메커니즘이 아직 바뀌고 있는데 그림을 반복해서 다시 만드는 것은 낭비입니다.

## 「생성 → 넣기 → 테스트」 루프

플레이스홀더 빌드가 대체로 돌아가게 되면, 이미지 생성은 한 번에 끝나는 단계가 아니라 **반복 루프**가 됩니다：

1. **생성**——특정 요소(플레이어, 코인, 적, 배경……)의 이미지를 생성합니다.
2. **넣기**——프로젝트에 저장하고, 코드에서 플레이스홀더 대신 연결합니다.
3. **실행하고 디버그**——실제로 프로젝트를 돌려서, **실제 씬**에서·**실제 크기**로·**실제 배경** 앞에서 결과를 봅니다.
4. **재생성**——본 결과를 바탕으로 요청을 조정해 다시 생성합니다.

보통 에셋 하나마다 이 루프를 여러 번 돌게 됩니다. 이미지를 따로 떼어 보면 알 수 있는 게 거의 없습니다. **돌아가는 씬 안에서** 봐야 그것이 통하는지 알 수 있습니다.

ANGEL 에서의 연결 방식：

- 프로젝트를 만들 때 이미지 생성이 포함된 템플릿을 고르세요——**Default(+이미지 생성)** 또는 **Extended(+이미지 생성)**——그러면 프로젝트에 resource-provider 라는 agent 가 포함됩니다. (프로젝트 생성과 열기（New/Open/Save）)[project-io.md] 참조.
- 생성된 이미지는 `assets/generated/images/` 아래에 저장되고, 그 경로가 agent 에게 다시 전달되므로, agent 는 그것을 참조하거나 Create Sprite 같은 도구에 넘길 수 있습니다. (Create Sprite)[create-sprite.md] 참조.
- 이미지 생성은 현재 OpenAI(API key) 의 기능입니다. **설정 → Agent Model** 에서 특정 이미지 모델을 고르거나 auto 로 둘 수 있습니다.

## 매우 중요한 기대치：품질은 보장되지 않는다

이것은 분명히 말해 둘 가치가 있습니다：

**현재 각 업체의 이미지 모델은——예외 없이——생성 이미지를 스타일화된 특정 씬에 완벽하게 어울리게 만들 만큼의 능력이 아직 없습니다. 최종 결과는 보장되지 않습니다.**

실제로 이는 다음을 의미합니다：

- 생성 이미지가 단독으로는 괜찮아 보여도, 씬에 넣는 순간 어색해질 수 있습니다——스타일이 안 맞고, 비율이 안 맞고, 실루엣이 안 맞고, 배경 앞에서의 색이 안 맞습니다.
- 다수의 에셋에 걸쳐 **일관된 아트 스타일**을 맞추는 것은 특히 어렵습니다.
- 엄격한 제약(정확한 포즈, 정확한 시점, 픽셀 단위로 정확한 가장자리, 깔끔한 투명 누끼, "같은 캐릭터지만 왼쪽을 향한 모습")은 안정적으로 충족되지 않는 경우가 많습니다.
- 반복은 도움이 되지만 한계가 있습니다. 현재 모델로는 도달할 수 없는 모습도 있습니다.

그래서 건강한 사용법은 다음과 같습니다：

- 생성 아트를 **플레이스홀더에서 "쓸 만한" 수준으로 빠르게 도달하는 수단**으로 여기고, 최종 출시 가능한·스타일이 완벽히 통일된 아트를 얻는 수단으로는 생각하지 마세요.
- 프롬프트에서는 중요한 점(대상, 실루엣, 색 팔레트, 배경이 투명인지 단색인지)을 구체적으로 쓰되, 일부 요청은 실현되지 않는다는 것을 받아들이세요.
- **마지막 마무리는 직접 한다**는 각오를 하세요——수작업 보정, 또는 가장 중요한 에셋은 손으로 만든 아트로 교체.
- 어떤 에셋이 정말로 스타일을 맞춰야 하는지 판단하고, 거기에 반복을 쓰세요. 덜 중요한 에셋은 거칠게 두세요.

## 실용적인 결론

- 먼저 플레이스홀더로 메커니즘을 맞추세요. 돌아간 다음에 이미지 생성을 들이세요.
- 「생성 → 넣기 → 실행 → 재생성」 루프를 전제로 하고, 실제 씬 안에서 좋고 나쁨을 판단하세요.
- 완벽하고 스타일이 완전히 맞는 결과를 기대하지 마세요——현재 모델은 그것을 보장할 수 없으므로, 반복과 수작업 마무리를 염두에 두세요.
