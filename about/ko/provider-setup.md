# Provider 설정

> 이 페이지에서는 모델 Provider, 모델 이름, 관련 접근 자격 증명을 설정하는 방법을 설명합니다.

## 현재 설정할 수 있는 것

모델 설정에서 현재 설정할 수 있는 주요 항목은 다음과 같습니다：

- Provider 유형
- 호출 방식 / Method
- 텍스트 모델 이름
- 이미지 모델 이름
- API Key / OAuth（provider 에 따라 다름）

## 현재 연결된 Provider

현재 GUI 는 이미 다음 Provider 에 연결되었거나 연결할 준비가 되어 있습니다：

- OpenAI
- Anthropic
- Google
- xAI（Grok）
- DeepSeek

그중：

- **OpenAI** 는 현재 `API Key` 와 `OAuth` 두 가지 방식을 지원
- **Anthropic / Google / xAI / DeepSeek** 는 현재 주로 `API Key` 방식으로 설정

환경이 정상적으로 작동하는지 빠르게 확인하고 싶다면, 가장 간단한 방법은 보통：

1. Provider 를 선택
2. 모델 이름과 자격 증명을 입력
3. 설정을 저장
4. Agent Chat 을 열고 가능한 한 간단한 메시지를 보내 정상적으로 응답하는지 확인

이것이 「Key 가 사용 가능한지」를 확인하는 가장 직접적인 방법입니다.

## 세션 도중에 Provider 를 전환하는 것에 대하여

같은 세션 도중에 Provider 를 전환하는 지원은 현재로서는 아직 상당히 제한적이므로, 안정적인 워크플로로 권장하지 않습니다.

이유는 간단합니다. Provider 가 다르면 요청 형식, 컨텍스트 구성 방식, 응답 구조, 도구 호출 세부 사항이 완전히 같지 않습니다. UI 상으로는 단순히 하나의 대화를 이어가는 것처럼 보여도, 내부 컨텍스트가 깔끔하게 이어진다는 보장은 없습니다.

따라서 현재로서 더 안전한 권장 사항은：

- **Provider 를 전환하려면 가능한 한 새 세션에서 시작하기**
- 같은 세션 기록이 서로 다른 Provider 사이에서 완벽하게 매끄럽게 이어진다고 당연시하지 않기

서로 다른 모델을 가볍게 테스트하는 정도라면 위험은 보통 작습니다. 그러나 현재 세션에 이미 많은 컨텍스트, 도구 호출, 이미지 입력이 포함되어 있다면, 도중에 Provider 를 전환하면 동작 차이가 생기기 더 쉽습니다.

## Humanize：아직 실험적인 미완성 기능

모델 설정에는 `Humanize` 관련 스위치도 있습니다.

그 목표는 응답을 더 자연스럽고 사람이 말하는 것처럼 만들어, 지나치게 기계적이거나 템플릿 같지 않게 하는 것입니다.

다만 이 부분은 현재로서는 **실험적·미완성 기능** 으로 다루는 편이 좋습니다：

- 때로는 표현을 더 자연스럽게 만들기도 함
- 때로는 불안정한 스타일 변화를 가져오기도 함
- 아직 완전히 성숙한 정식 기능으로 다루어서는 안 됨

출력 스타일을 중시한다면 켜고 끈 상태를 비교해 볼 수 있습니다. 그러나 지금은 안정성, 예측 가능성, 문제 해결의 용이성을 우선한다면, 당분간 꺼 두는 편이 보통 더 낫습니다.

## 실용적인 제안

Provider 를 처음 설정한다면, 권장되는 순서는 보통：

1. 먼저 Provider 하나를 선택
2. 모델 이름과 자격 증명을 입력
3. Agent Chat 으로 짧은 메시지를 보내 작동을 확인
4. 기본이 안정되면 humanize 같은 추가 옵션을 켤지 검토

이렇게 하면 「기본 연결성 문제」와 「스타일 추가 기능 문제」를 분리해서 보기 더 쉬워집니다.
