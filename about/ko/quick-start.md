# Quick Start：처음 실행한 뒤 할 일

> ANGEL GUI를 처음 사용한다면, 아래 순서대로 최소 검증 흐름을 한 번 진행하는 것을 권장합니다.

## 1. 먼저 Provider / API Key를 설정한다

먼저 모델 관련 설정을 열고, 사용할 Provider와 액세스 자격 증명을 입력합니다.

최소한 다음 항목을 완료하는 것을 권장합니다:

- Provider 선택
- 호출 방식 / Method 확인
- 모델 이름 입력
- 현재 Provider가 자격 증명을 요구하면 API Key 또는 OAuth 정보 입력

이전에 설정한 적이 없다면 먼저 여기를 참고하세요:

- (Provider 설정)[provider-setup.md]

## 2. 대화 한 번으로 Key가 작동하는지 확인한다

설정을 마치면 Agent Chat을 열고, 가능한 한 간단한 테스트 메시지를 보냅니다. 예:

- `hello`
- `test`
- `안녕하세요, 연결이 정상인지 확인할 수 있도록 짧게 한마디 답해 주세요.`

Agent가 정상적으로 답하면, 보통 다음을 의미합니다:

- Provider 설정이 대체로 올바름
- Key / Token이 유효함
- 현재 모델 요청 경로가 연결되어 있음

이 단계에서 이미 대화가 실패한다면, 프로젝트 흐름을 계속 진행하기보다 먼저 Provider 설정을 다시 확인하는 것을 권장합니다.

## 3. Default 프로젝트를 새로 만든다

다음으로 **File → New Project**로 새 프로젝트를 만들고 다음을 선택합니다:

- `Default`

이렇게 하면 먼저 가장 작은 템플릿으로 로컬 프로젝트 흐름이 정상인지 확인할 수 있습니다.

생성 후, 프로젝트가 정상적으로 열리고 기본 내용과 기본 UI가 보이는지 확인하세요.

프로젝트 생성 흐름이 아직 익숙하지 않다면 이어서 여기를 참고하세요:

- (프로젝트 생성과 열기（New/Open/Save）)[project-io.md]

## 4. 프로젝트를 한 번 컴파일하여 환경을 확인한다

프로젝트 생성 후 **Execute** 메뉴에서 컴파일을 한 번 실행합니다.

가장 기본적인 단계부터 시작하는 것을 권장합니다:

- Compile

컴파일이 성공하면, 보통 다음을 의미합니다:

- 로컬 프로젝트 템플릿을 사용할 수 있음
- 컴파일 경로를 사용할 수 있음
- 현재 프로젝트 환경이 대체로 정상임

필요하다면 이어서 다음도 시도할 수 있습니다:

- Run
- Test

관련 설명은 다음을 참고하세요:

- (실행과 구동（Compile/Run/Test）)[execute.md]

## 5. 위 단계가 모두 문제없으면 정상적으로 사용을 시작할 수 있다

아래 항목이 모두 통과하면, 보통 환경이 사용할 준비가 충분히 된 것입니다:

- Provider / API Key 설정 완료
- Agent Chat에서 정상적으로 대화 가능
- `Default` 프로젝트를 성공적으로 생성 가능
- 프로젝트를 성공적으로 컴파일 가능

이 모두가 정상이라면 그래프 편집, Agent, 리소스 도구 및 기타 기능으로 넘어갈 수 있습니다.
