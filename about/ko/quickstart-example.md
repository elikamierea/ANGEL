# 사용 예

> 이 페이지에서는 ANGEL GUI 를 처음부터 시험해 보기 위한 최소 예시 흐름을 제시합니다. 목표는 처음부터 그래프를 매우 복잡하게 만드는 것이 아니라, 먼저 한 번의 완전한 경험을 해 보는 것입니다：프로젝트 생성 → 설계 그래프 작성 → agent 에게 구현 요청 → 컴파일 및 실행.

## 목표

아주 작은 샘플 프로젝트를 만들 것입니다：

- 플레이어가 씬 중앙에 등장
- 플레이어는 이동과 회전이 가능
- 씬에 코인과 적이 생성됨
- 플레이어는 코인을 모아 점수를 얻음
- 적이 플레이어에 닿으면 플레이어가 사라짐
- 플레이어가 사라진 뒤, 적이 화면 밖으로 나가고, 그다음 플레이어가 다시 생성됨

## 1단계：`Default` 새 프로젝트 만들기

먼저 사용합니다：

- **File → New Project**

새 프로젝트를 만들고 다음을 선택합니다：

- `Default`

이렇게 하면 처음부터 불필요한 구조를 너무 많이 들이지 않아, 첫 시험에 더 적합합니다.

## 2단계：메인 노드 `씬` 만들기

Graph 에 들어간 뒤, 노드를 하나 만들고 다음 이름을 붙입니다：

- `씬`

다음 내용을 입력합니다：

```text
창 크기는 960*540. 처음에 플레이어는 화면 중앙에 있다.

씬에 코인이 생성되고, 플레이어는 그것을 모아 점수를 올릴 수 있다.

씬에 적이 생성되고, 플레이어에 닿으면 게임이 끝난다.

1초마다 한 번 확인한다. 코인이 없으면 화면 내 무작위 위치에 코인 1개를 생성한다. 코인 수가 3 미만이면 20% 확률로 코인 1개를 생성한다.

플레이어가 코인을 3개 모을 때마다, 화면 밖 무작위 위치에 적 1마리를 생성한다. 생성 규칙：중심에서 시작해, 0~360도 범위에서 균등 무작위로 각도를 고르고, 그 방향의 바깥쪽 선 위에서 창 경계로부터 최소 100픽셀 떨어진 가장 가까운 점을 고른다.

적이 플레이어에 닿으면 플레이어가 사라진다. 플레이어가 사라진 뒤 적은 화면 밖으로 나가려 한다. 모든 적이 화면 밖으로 나가면 플레이어를 다시 생성한다.
```

이 노드는 게임플레이 샘플 전체의 마스터 씬 규칙 집합으로 이해할 수 있습니다.

## 3단계：그 내부에 자식 노드 3개 만들기

다음으로, `씬` 노드 내부에 세 개의 노드를 만듭니다：

- `플레이어`
- `코인`
- `적`

### 노드：플레이어

다음 내용을 입력합니다：

```text
플레이어를 나타내는 흰색 이등변 삼각형을 그린다. 밑변은 너비 24픽셀, 높이는 32픽셀.

플레이어는 A/D 키로 초당 180도 회전한다. W를 누르고 있으면 초당 300픽셀로 전진한다. S를 누르고 있으면 초당 100픽셀로 후진한다.
```

### 노드：코인

다음 내용을 입력합니다：

```text
모습：반지름 8픽셀의 노란 원
```

### 노드：적

다음 내용을 입력합니다：

```text
모습：빨간 직사각형

속도는 초당 100~200 사이이며, 플레이어를 향해 이동한다. 플레이어가 존재하지 않으면 가장 가까운 경계를 향해 화면 밖으로 이동한다.

너비와 높이는 16~40픽셀 사이.

이 세 값은 생성 시 무작위로 정해지고, 이후에는 고정된다.
```

## 4단계：엣지 관계 만들기

노드를 만든 뒤, 두 개의 관계 엣지를 추가합니다.

### 엣지：적 → 플레이어

relation 을 다음으로 설정합니다：

- `destroys`

다음 내용을 입력합니다：

```text
적이 플레이어에 닿으면 플레이어가 사라진다.
```

### 엣지：플레이어 → 코인

relation 을 다음으로 설정합니다：

- `collects`

다음 내용을 입력합니다：

```text
플레이어가 코인에 닿으면 코인이 수집된다.
```

여기까지 하면, 최소하지만 완전한 설계 구조를 갖추게 됩니다：

- 마스터 씬 규칙 집합
- 오브젝트 노드
- 그 오브젝트 간의 관계

이것만으로도 agent 구현 테스트로 쓰기에 충분합니다.

## 5단계：programmer 에이전트에게 구현 요청하기

위의 노드와 엣지가 모두 준비되면, **programmer** 로 전환한 뒤 이렇게 말합니다：

```text
안녕하세요, 이 소프트웨어를 시험해 보고 있습니다. 샘플 프로젝트를 제공했습니다. 구현해 주세요.
```

이 단계의 목적은, programmer 에이전트가 방금 만든 Graph 구조를 코드로 바꾸도록 해 보는 것입니다.

## 6단계：결과 기다리기

메시지를 보낸 뒤, programmer 에이전트의 응답을 기다립니다.

이 단계는 즉시 끝나지 않을 수 있습니다. 다음이 필요할 수 있기 때문입니다：

- 현재 Graph 구조 읽기
- 노드와 엣지가 표현하는 규칙 이해
- 코드를 어디에 둘지 정리
- 프로젝트 파일에 차례로 작성

따라서 여기서의 핵심은：

- 먼저 한 차례의 구현을 완료하게 하기
- 제공한 설계 구조를 올바르게 이해하는지 관찰하기

## 7단계：Execute 로 컴파일하고 실행하기

programmer 에이전트가 끝나면, 상단 메뉴를 사용합니다：

- **Execute**

먼저 실행합니다：

- **Compile Project**

컴파일이 성공하면 이어서：

- **Run Project**

이 시점에서 한 번의 완전한 시험을 마친 것입니다：

- Graph 로 설계 작성
- agent 로 그 설계를 읽고 구현
- Execute 로 결과를 컴파일하고 실행

이것이 이 튜토리얼의 종착점입니다.

## 이 사용 예가 검증하려는 것

이 흐름 전체가 작동하면, 보통 다음을 의미합니다：

- 기본 프로젝트를 만드는 법을 알게 됨
- 노드와 엣지로 설계를 표현하는 법을 알게 됨
- programmer 에이전트가 그 설계 구조를 읽고 활용할 수 있음
- 로컬 컴파일과 실행 파이프라인이 기본적으로 작동함

다시 말해, 이 예를 매끄럽게 완료할 수 있다면, ANGEL GUI 핵심 워크플로의 첫 완전한 경험을 이미 마친 것입니다.
