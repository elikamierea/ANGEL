# 执行与运行（Execute）

Execute 菜单主要负责把当前项目编译、运行和测试起来。

## 这些项目是怎么被产出的

当前项目产出的游戏，并不是每次都从零开始搭一个全新的工程。

更准确地说，它是基于一个**固定的 C++ 项目模板**来工作的：

- 底层已经有一套预先准备好的工程结构
- 包括引擎层、平台层、资源目录、构建配置和基础入口
- 实际项目开发时，主要由 **coding agent** 根据已有设计，往这个模板里逐步补充和修改内容

你可以把它理解成：

- 模板负责提供稳定骨架
- 设计决定要做什么
- coding agent 负责把设计逐步落进这个骨架里

所以在日常使用中，`Compile / Run / Test` 并不只是“编译一堆手写代码”，而更像是在验证：

- 当前设计落地后的代码是否已经成形
- agent 写入的内容是否和模板结构兼容
- 本地构建环境是否正常

## Execute 菜单包含什么

- **Compile Project**：编译工程
- **Run Project**：运行项目
- **Run Project (Debug)**：调试运行
- **Run Test**：运行指定测试

建议顺序通常是：

1. 先 **Compile**
2. 再 **Run**
3. 如果有特定验证目标，再用 **Test**

这样更容易把“编译失败”和“运行期失败”分开看。

## Compile 是在验证什么

一次成功的编译，通常至少说明：

- 当前项目代码结构基本完整
- 模板工程本身没有被破坏
- 本地编译链路可用
- agent 最近写入的代码没有立即导致构建中断

所以当你第一次打开一个新项目，或者刚做完一轮较大的 agent 修改后，`Compile` 往往是最重要的第一步。

## 编译时常见问题，以及可以先怎么排查

编译失败并不一定说明项目整体坏了，很多时候只是某一层出了问题。下面是比较常见的几类情况。

### 1. Provider / Agent 输出的代码本身有问题

例如：

- 生成的代码语法不完整
- 函数名、类型名、头文件引用不一致
- 改动之间互相没有对齐

这类问题通常表现为：

- 编译器直接报 C++ 语法错误
- 某个 symbol / type / include 找不到
- 某次 agent 改动后突然开始报错

可以先尝试：

- 回看最近一轮 agent 改了哪些内容
- 先从第一条编译错误开始看，不要被后续连锁报错干扰
- 优先修最靠前、最基础的错误

### 2. 项目结构或文件落点不对

例如：

- 文件写到了不合适的位置
- 新增代码和模板既有结构没有对齐
- 资源路径、头文件路径、源文件组织方式不匹配

这类问题通常表现为：

- include 路径错误
- 找不到源文件或资源文件
- 某些内容明明“写了”，但构建链路没有正确吃到

可以先尝试：

- 检查相关文件是不是放在预期目录
- 检查路径引用是否和项目目录结构一致
- 检查改动是不是落在了正确的项目层，而不是写偏到别的区域

### 3. 本地编译环境问题

例如：

- CMake / 编译器环境不完整
- 构建工具不可用
- 本地依赖或工具链状态异常

这类问题通常表现为：

- 配置阶段就失败
- 还没开始正式编译就报工具链错误
- 不同项目都编不过，而不是某个项目独有问题

可以先尝试：

- 先确认这是不是“项目代码问题”还是“环境问题”
- 如果连最小项目也无法编译，优先怀疑环境
- 回到 Quick Start 的最小验证流程重新检查一遍

## 运行与调试

### Run Project

`Run Project` 用来直接运行当前项目。

它适合在以下场景使用：

- 编译刚通过，想马上看当前效果
- 快速确认程序是否能正常启动
- 验证最近一轮设计或代码改动有没有明显行为变化

### Run Project (Debug)

`Run Project (Debug)` 更适合排查运行期问题，例如：

- 能编译，但启动后行为不对
- 有日志、状态或流程想进一步观察
- 想区分“编译期没问题”和“运行期逻辑有问题”

### Run Test

`Run Test` 适合在你已经知道要验证哪个测试目标时使用。

它比直接运行整个项目更聚焦，适合：

- 针对单个测试名验证
- 复现特定问题
- 对某个模块做更窄的确认

## 一个实用建议

如果你刚做完一轮改动，最稳的顺序通常是：

1. 先 **Compile**
2. 如果编译通过，再 **Run**
3. 如果运行异常，再考虑 **Debug / Test**

如果连 `Compile` 都过不去，就先不要急着看运行效果；先把最前面的构建错误解决掉，效率通常更高。
