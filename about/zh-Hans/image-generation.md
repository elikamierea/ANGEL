# 图像生成

> 本页讲的是如何让 agent 为你的项目生成图像，以及——同样重要的——你应该对它抱有怎样的现实预期。

## 图像生成在工作流中的位置

图像生成通常**不是**你最先做的事。更实际的顺序是：

1. 先搭好设计（Graph），让 agent **用占位图**（placeholder：纯色块、简单的矩形/圆形等）来实现玩法和逻辑。
2. 让这套基于占位图的版本能**编译并运行**，确保机制大致正确。
3. **到这一步之后**，再开始用生成的图像替换占位图。

原因很简单：美术是最后才值得投入的部分。如果机制还在改，反复重做美术就是浪费。

## 「生成 → 放进去 → 测试」的循环

当占位版本大致能跑起来后，图像生成就变成一个**反复迭代的循环**，而不是一次性的步骤：

1. **生成**——为某个具体元素（玩家、金币、敌人、背景……）生成一张图。
2. **放进去**——把它存进项目，并在代码里替换掉原来的占位图。
3. **运行并调试**——真正把项目跑起来，在**真实场景**里、**真实尺寸**下、**真实背景**前看效果。
4. **重新生成**——根据看到的效果，调整描述再生成一次。

每个素材通常都要绕这个循环好几遍。单看一张孤立的图说明不了什么；**把它放进运行中的场景里看**，才知道它行不行。

在 ANGEL 里的接法：

- 创建项目时选带图像生成的模板——**Default（+图像生成）** 或 **Extended（+图像生成）**——这样项目里就会带上 resource-provider 这个 agent。参见 (项目创建与打开（New/Open/Save）)[project-io.md]。
- 生成的图会保存在 `assets/generated/images/` 下，其路径会回传给 agent，所以它能引用这些图、并喂给 Create Sprite 等工具。参见 (Create Sprite)[create-sprite.md]。
- 图像生成目前是 OpenAI（API key）的能力。你可以在 **设置 → Agent Model** 里选一个具体的图像模型，或保持 auto。

## 一个非常重要的预期：效果无法保证

这一点值得直说：

**当前各家的图像模型——无一例外——都还不足以让生成的图片完美贴合一个风格化的、具体的场景。最终效果无法保证。**

具体来说意味着：

- 一张生成的图单看可能没问题，但一放进你的场景就不对劲——风格不对、比例不对、剪影不对、在背景前的颜色不对。
- 在大量素材之间保持**统一的美术风格**尤其困难。
- 严格的约束（精确的姿态、精确的视角、像素级精确的边缘、干净的透明抠图、「同一个角色但转向左边」）往往无法稳定达成。
- 多迭代会有帮助，但存在上限：有些效果用当前模型就是做不到。

所以健康的用法是：

- 把生成的美术当作**从占位图快速到达「够用」的手段**，而不是用来获得最终可交付、风格完美统一的成品美术。
- 描述里把关键点说具体（主体、剪影、配色、背景该透明还是纯色），但也要接受有些要求就是实现不了。
- 做好**最后一公里靠自己**的准备——手动修图，或把最重要的素材换成手工制作的美术。
- 想清楚哪些素材真的需要风格统一，把迭代花在那里；不重要的素材就让它粗糙着。

## 一个实用的结论

- 先在占位图上把机制做对；跑起来之后再引入图像生成。
- 预期是一个「生成 → 放进去 → 运行 → 重新生成」的循环，并且要在真实场景里判断效果。
- 不要指望完美、完全贴合风格的结果——当前模型无法保证这一点，所以要为迭代和手动收尾留出余地。
