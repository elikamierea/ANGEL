# Provider 配置

> 本页说明如何配置模型 Provider、模型名称与相关访问凭据。

## 目前可以配置什么

在模型设置里，目前可以配置的内容主要包括：

- Provider 类型
- 调用方式 / Method
- 文本模型名称
- 图片模型名称
- API Key / OAuth（视 provider 而定）

## 目前已接上的 Provider

当前 GUI 已经接入或对接了这些 Provider：

- OpenAI
- Anthropic
- Google
- xAI（Grok）
- DeepSeek

其中：

- **OpenAI** 目前支持 `API Key` 与 `OAuth` 两种方式
- **Anthropic / Google / xAI / DeepSeek** 当前主要按 `API Key` 方式配置

如果你只是想先验证环境是否正常，最简单的方法通常是：

1. 选好 Provider
2. 填好模型名与凭据
3. 保存设置
4. 打开 Agent Chat 发一条最简单的消息测试是否能正常回复

这就是最直接的“Key 是否可用”验证方式。

## 关于“中途切换 Provider”

目前对“在同一个会话中途切换 Provider”的支持还比较有限，不建议把它当成稳定工作流。

原因很简单：不同 Provider 的请求格式、上下文组织方式、返回结构和工具调用细节并不完全一样。即使表面上都是“继续聊天”，底层上下文也不一定能无损衔接。

所以当前更稳妥的建议是：

- **如果要换 Provider，尽量在新会话里开始**
- 不要默认指望“同一段会话历史”在不同 Provider 之间可以完全平滑续上

如果只是偶尔试一下不同模型，问题通常不大；但如果你已经在一个会话里跑了较多上下文、工具调用或图片输入，再中途切 Provider，就更容易出现行为差异。

## Humanize：目前仍是半成品尝试

模型设置里还有一个和 `Humanize` 相关的开关。

它的目标，是尝试让会话输出更自然、更像人在说话，而不是过于机械或模板化。

不过目前这部分仍然属于**半成品状态的尝试**，更适合当成实验性选项来看待：

- 有时会让表达更自然
- 有时也可能带来不稳定的风格变化
- 目前不建议把它理解成“已经完全成熟的正式功能” 

如果你在意输出风格，可以试着开关对比；但如果你现在更重视稳定性、可预期性和排查方便，通常建议先保持关闭。

## 一个实用建议

如果你是第一次配置 Provider，推荐顺序通常是：

1. 先选一个 Provider
2. 填写模型名称与凭据
3. 用 Agent Chat 发一条短消息验证可用性
4. 确认稳定后，再考虑是否打开 humanize 之类的附加选项

这样更容易把“基础连通性问题”和“风格附加功能问题”分开看。
