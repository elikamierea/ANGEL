# 使用例

> 本页给出一个从零开始试用 ANGEL GUI 的最小示例流程。目标不是一开始就把图做得非常复杂，而是先让你完整体验一次：建项目 → 建设计图 → 让 agent 实现 → 编译运行。

## 目标

我们将做一个很小的样例项目：

- 玩家在场景中央出现
- 可以移动和转向
- 场景里会生成金币与敌人
- 玩家拾取金币获得分数
- 敌人碰到玩家会让玩家消失
- 玩家消失后，敌人离场，再重新生成玩家

## 第一步：建立一个 `Default` 新项目

先用：

- **File → New Project**

创建一个新项目，并选择：

- `Default`

这样可以避免一开始引入太多额外结构，更适合做第一次试用。

## 第二步：建立主节点 `场景`

进入 Graph 后，创建一个节点，命名为：

- `场景`

将它的内容填写为：

```text
窗口大小为960*540。初始时，玩家在屏幕中心

场景中会生成金币，玩家可以拾取以提高分数。

场景中会生成敌人，碰到玩家后游戏结束

每秒进行一次检测，如果没有金币则在屏幕中随机位置生成一个金币。如果金币数量小于3则有20%几率生成一个金币


玩家每拾取3个金币，就在屏幕外随机位置生成一个敌人（生成方式为：从中心开始，随机选择一个角度（在0到360度内均匀随机），然后取此方向的延长线上选择最近的离窗口边界至少100像素的点）


敌人碰到玩家会使其消失。玩家消失后敌人会尝试离开屏幕。这时，在所有敌人离开屏幕后，重新生成玩家
```

这个节点可以理解为整个玩法样例的总场景规则。

## 第三步：在其内部建立 3 个子节点

接下来，在 `场景` 节点内部继续建立三个节点：

- `玩家`
- `金币`
- `敌人`

### 节点：玩家

内容填写为：

```text
绘制一个白色的等腰三角形以表示玩家。其底边长为24像素，高32像素。

玩家可以通过A/D键转向，角速度为180度每秒。按住W键向前移动，速度为300像素每秒。按住S键向后移动，速度为100像素每秒。
```

### 节点：金币

内容填写为：

```text
形象为黄色圆形，半径8像素
```

### 节点：敌人

内容填写为：

```text
形象为一个红色矩形

每秒速度在100到200之间，朝向玩家移动（如果玩家不存在则向屏幕外移动，方向朝向最近的边界）

长宽在16像素到40像素之间

其生成时，以上三个数值随机决定，之后不再改变
```

## 第四步：建立边关系

在节点建立完成后，继续建立两条关系边。

### 边：敌人 → 玩家

将 relation 改为：

- `destroys`

内容填写为：

```text
敌人碰到玩家后，玩家消失
```

### 边：玩家 → 金币

将 relation 改为：

- `collects`

内容填写为：

```text
玩家碰到金币时，将其拾起
```

到这里为止，你已经完成了一套最小但完整的设计结构：

- 有总场景规则
- 有对象节点
- 有对象间关系

这已经足够拿来作为一次 agent 实现测试。

## 第五步：让 programmer 开始实现

当上面的节点和边都完成后，切换到 **programmer**，然后对它说：

```text
你好，我在试用这个软件。我提供了一个样例项目，请将其实现
```

这一步的目的，是让 programmer 基于你刚刚建立的 Graph 结构，尝试把这个样例项目落地为代码。

## 第六步：等待结果

发送后，等待 programmer 返回结果。

这一步不一定会瞬间完成，因为它可能需要：

- 阅读当前 Graph 结构
- 理解节点与边表达的规则
- 组织代码落点
- 逐步写入项目文件

所以这里的重点是：

- 让它先完成一轮实现
- 观察它是否能正确理解你给出的设计结构

## 第七步：通过 Execute 编译和运行

当 programmer 完成后，使用顶部菜单中的：

- **Execute**

先进行：

- **Compile Project**

如果编译成功，再继续：

- **Run Project**

这样你就完成了一次完整试用：

- 用 Graph 写设计
- 用 agent 读取并实现设计
- 用 Execute 编译运行结果

这就是本教程的终点。

## 这个使用例想帮助你验证什么

如果这套流程整体跑通，通常就说明：

- 你已经会建立基本项目
- 你已经会用节点和边表达设计
- programmer 能读取并利用这套设计结构
- 本地编译与运行链路基本正常

换句话说，如果你能顺利完成这个例子，就已经对 ANGEL GUI 的核心工作流有了第一轮完整体验。
