# 執行與運行（Execute）

Execute 選單主要負責把目前專案編譯、執行和測試起來。

## 這些專案是怎麼被產出的

目前專案產出的遊戲，並不是每次都從零開始搭一個全新的工程。

更準確地說，它是基於一個**固定的 C++ 專案範本**來工作的：

- 底層已經有一套預先準備好的工程結構
- 包括引擎層、平台層、資源目錄、建置設定和基礎進入點
- 實際專案開發時，主要由 **coding agent** 根據既有設計，往這個範本裡逐步補充和修改內容

你可以把它理解成：

- 範本負責提供穩定骨架
- 設計決定要做什麼
- coding agent 負責把設計逐步落進這個骨架裡

所以在日常使用中，`Compile / Run / Test` 並不只是「編譯一堆手寫程式碼」，而更像是在驗證：

- 目前設計落地後的程式碼是否已經成形
- agent 寫入的內容是否和範本結構相容
- 本機建置環境是否正常

## Execute 選單包含什麼

- **Compile Project**：編譯工程
- **Run Project**：執行專案
- **Run Project (Debug)**：偵錯執行
- **Run Test**：執行指定測試

建議順序通常是：

1. 先 **Compile**
2. 再 **Run**
3. 如果有特定驗證目標，再用 **Test**

這樣更容易把「編譯失敗」和「執行期失敗」分開看。

## Compile 是在驗證什麼

一次成功的編譯，通常至少說明：

- 目前專案程式碼結構基本完整
- 範本工程本身沒有被破壞
- 本機編譯鏈路可用
- agent 最近寫入的程式碼沒有立即導致建置中斷

所以當你第一次開啟一個新專案，或者剛做完一輪較大的 agent 修改後，`Compile` 往往是最重要的第一步。

## 編譯時常見問題，以及可以先怎麼排查

編譯失敗並不一定說明專案整體壞了，很多時候只是某一層出了問題。下面是比較常見的幾類情況。

### 1. Provider / Agent 輸出的程式碼本身有問題

例如：

- 生成的程式碼語法不完整
- 函式名、型別名、標頭檔引用不一致
- 改動之間互相沒有對齊

這類問題通常表現為：

- 編譯器直接報 C++ 語法錯誤
- 某個 symbol / type / include 找不到
- 某次 agent 改動後突然開始報錯

可以先嘗試：

- 回看最近一輪 agent 改了哪些內容
- 先從第一條編譯錯誤開始看，不要被後續連鎖報錯干擾
- 優先修最靠前、最基礎的錯誤

### 2. 專案結構或檔案落點不對

例如：

- 檔案寫到了不合適的位置
- 新增程式碼和範本既有結構沒有對齊
- 資源路徑、標頭檔路徑、原始檔組織方式不匹配

這類問題通常表現為：

- include 路徑錯誤
- 找不到原始檔或資源檔案
- 某些內容明明「寫了」，但建置鏈路沒有正確吃到

可以先嘗試：

- 檢查相關檔案是不是放在預期目錄
- 檢查路徑引用是否和專案目錄結構一致
- 檢查改動是不是落在了正確的專案層，而不是寫偏到別的區域

### 3. 本機編譯環境問題

例如：

- CMake / 編譯器環境不完整
- 建置工具不可用
- 本機相依或工具鏈狀態異常

這類問題通常表現為：

- 設定階段就失敗
- 還沒開始正式編譯就報工具鏈錯誤
- 不同專案都編不過，而不是某個專案獨有問題

可以先嘗試：

- 先確認這是不是「專案程式碼問題」還是「環境問題」
- 如果連最小專案也無法編譯，優先懷疑環境
- 回到 Quick Start 的最小驗證流程重新檢查一遍

## 執行與偵錯

### Run Project

`Run Project` 用來直接執行目前專案。

它適合在以下場景使用：

- 編譯剛通過，想馬上看目前效果
- 快速確認程式是否能正常啟動
- 驗證最近一輪設計或程式碼改動有沒有明顯行為變化

### Run Project (Debug)

`Run Project (Debug)` 更適合排查執行期問題，例如：

- 能編譯，但啟動後行為不對
- 有記錄檔、狀態或流程想進一步觀察
- 想區分「編譯期沒問題」和「執行期邏輯有問題」

### Run Test

`Run Test` 適合在你已經知道要驗證哪個測試目標時使用。

它比直接執行整個專案更聚焦，適合：

- 針對單個測試名驗證
- 重現特定問題
- 對某個模組做更窄的確認

## 一個實用建議

如果你剛做完一輪改動，最穩的順序通常是：

1. 先 **Compile**
2. 如果編譯通過，再 **Run**
3. 如果執行異常，再考慮 **Debug / Test**

如果連 `Compile` 都過不去，就先不要急著看執行效果；先把最前面的建置錯誤解決掉，效率通常更高。
