# 專案建立與開啟（Project I/O）

## New Project

建立新專案時，需要選擇一個起始範本。範本的區別在於搭建多少**規模**（結構與 agent）。

### Default

`Default` 是最小的起點——2 層結構，只配一個編碼 agent。它更適合這類流程：

- 已經有了基本設計
- 不打算先鋪很多前置結構
- 想直接開始寫遊戲層程式碼
- 更關心先把一個最小可執行閉環做起來

換句話說，`Default` 更偏向「**有設計，然後直接開始動程式碼**」的工作方式。

它也很適合第一次驗證本機環境，因為路徑更短、干擾更少。

### Extended

`Extended` 是更大的起點——4 層結構，配有設計、編排與編碼 agent。它更適合這類流程：

- 已經有了一個初步設計
- 接下來還想繼續完善設計
- 希望先對程式碼結構與實作步驟做一些規劃
- 最後再逐步進入實際編碼

換句話說，`Extended` 更偏向「**先整理設計與結構，再進入實作**」的工作方式。

## 專案資料夾大概長什麼樣

新專案建立後，本質上會產生一個工程目錄。你可以大致這樣理解它的結構：

### 1. 圖相關資訊

圖編輯器中的節點、邊、層級、UI 狀態等專案資料，會儲存在專案設定檔中。

目前專案是按「**專案目錄 + 專案設定檔**」來組織的，開啟專案時也是直接選擇專案目錄，再由 GUI 去辨識裡面的專案設定。

你可以把這部分理解成：

- 圖結構資料
- 編輯器狀態資料
- 與目前專案相關的 GUI 儲存資訊

### 2. 程式碼相關部分

程式碼工程主體會放在標準工程目錄中，核心通常包括：

- `src/game/`：遊戲層程式碼，最主要的實際實作區域
- `src/engine/`：底層引擎部分
- `src/platform/`：平台層
- `vendor/`：第三方相依或隨範本散布的程式庫檔案
- `tools/`：一些隨專案附帶的工具指令碼或內建工具

如果你只是日常繼續做功能，通常最常接觸的是：

- `src/game/`

### 3. 資源檔案放在哪裡

專案資源目前主要放在：

- `src/assets/sprites/`
- `src/assets/fonts/`
- `src/assets/audio/`
- `src/assets/other/`

所以可以簡單理解為：

- Sprite 資源放在 `sprites`
- 字型資源放在 `fonts`
- 音訊資源放在 `audio`
- 其他雜項資源放在 `other`

這也是為什麼在資源相關工具（比如 Create Sprite / Create Font）裡，最終通常還是會落回這些目錄。

### 4. Agent 相關資訊

如果專案啟用了 Agent 側的專案內記憶/上下文檔案，它們通常會按 agent 維度組織在單獨目錄裡。

你可以把這部分理解成：

- 不同 agent 各自的記憶檔案
- 一些用於工作階段初始化的上下文材料

這部分不是普通遊戲資源，也不是底層引擎程式碼，而更像是「這個專案給 agent 使用的輔助資訊層」。

## Open / Save / Save As

### Open

- **Open**：開啟既有專案
- 目前工作流是直接選擇專案目錄，而不是只選某一個零散檔案

### Save

- **Save**：儲存目前專案狀態
- 這裡通常包括圖編輯器裡的專案資料，以及和目前專案繫結的相關儲存內容

### Save As

- **Save As**：將目前專案另存到其他位置

## 一個實用理解

如果只想快速理解 New Project / Open / Save，可以先這樣記：

- `Default`：更適合「有設計，直接開始寫程式碼」
- `Extended`：更適合「先設計/完善/規劃，再實作」
- 圖資料儲存在專案設定中
- 程式碼主要在 `src/`
- 資源主要在 `src/assets/`
- Agent 相關上下文資訊會和專案一起組織，但屬於單獨的資訊層
