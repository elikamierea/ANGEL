# Provider 設定

> 本頁說明如何設定模型 Provider、模型名稱與相關存取憑證。

## 目前可以設定什麼

在模型設定裡，目前可以設定的內容主要包括：

- Provider 類型
- 呼叫方式 / Method
- 文字模型名稱
- 圖片模型名稱
- API Key / OAuth（視 provider 而定）

## 目前已接上的 Provider

目前 GUI 已經接入或對接了這些 Provider：

- OpenAI
- Anthropic
- Google
- xAI（Grok）
- DeepSeek

其中：

- **OpenAI** 目前支援 `API Key` 與 `OAuth` 兩種方式
- **Anthropic / Google / xAI / DeepSeek** 目前主要按 `API Key` 方式設定

如果你只是想先驗證環境是否正常，最簡單的方法通常是：

1. 選好 Provider
2. 填好模型名與憑證
3. 儲存設定
4. 開啟 Agent Chat 發一條最簡單的訊息測試是否能正常回覆

這就是最直接的「Key 是否可用」驗證方式。

## 關於「中途切換 Provider」

目前對「在同一個工作階段中途切換 Provider」的支援還比較有限，不建議把它當成穩定工作流。

原因很簡單：不同 Provider 的請求格式、上下文組織方式、回傳結構和工具呼叫細節並不完全一樣。即使表面上都是「繼續聊天」，底層上下文也不一定能無損銜接。

所以目前更穩妥的建議是：

- **如果要換 Provider，盡量在新工作階段裡開始**
- 不要預設指望「同一段工作階段歷史」在不同 Provider 之間可以完全平滑接續

如果只是偶爾試一下不同模型，問題通常不大；但如果你已經在一個工作階段裡跑了較多上下文、工具呼叫或圖片輸入，再中途切 Provider，就更容易出現行為差異。

## Humanize：目前仍是半成品嘗試

模型設定裡還有一個和 `Humanize` 相關的開關。

它的目標，是嘗試讓會話輸出更自然、更像人在說話，而不是過於機械或樣板化。

不過目前這部分仍然屬於**半成品狀態的嘗試**，更適合當成實驗性選項來看待：

- 有時會讓表達更自然
- 有時也可能帶來不穩定的風格變化
- 目前不建議把它理解成「已經完全成熟的正式功能」

如果你在意輸出風格，可以試著開關對比；但如果你現在更重視穩定性、可預期性和排查方便，通常建議先保持關閉。

## 一個實用建議

如果你是第一次設定 Provider，推薦順序通常是：

1. 先選一個 Provider
2. 填寫模型名稱與憑證
3. 用 Agent Chat 發一條短訊息驗證可用性
4. 確認穩定後，再考慮是否開啟 humanize 之類的附加選項

這樣更容易把「基礎連通性問題」和「風格附加功能問題」分開看。
