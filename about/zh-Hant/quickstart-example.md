# 使用範例

> 本頁給出一個從零開始試用 ANGEL GUI 的最小範例流程。目標不是一開始就把圖做得非常複雜，而是先讓你完整體驗一次：建專案 → 建設計圖 → 讓 agent 實作 → 編譯執行。

## 目標

我們將做一個很小的範例專案：

- 玩家在場景中央出現
- 可以移動和轉向
- 場景裡會生成金幣與敵人
- 玩家拾取金幣獲得分數
- 敵人碰到玩家會讓玩家消失
- 玩家消失後，敵人離場，再重新生成玩家

## 第一步：建立一個 `Default` 新專案

先用：

- **File → New Project**

建立一個新專案，並選擇：

- `Default`

這樣可以避免一開始引入太多額外結構，更適合做第一次試用。

## 第二步：建立主節點 `場景`

進入 Graph 後，建立一個節點，命名為：

- `場景`

將它的內容填寫為：

```text
視窗大小為960*540。初始時，玩家在螢幕中心

場景中會生成金幣，玩家可以拾取以提高分數。

場景中會生成敵人，碰到玩家後遊戲結束

每秒進行一次偵測，如果沒有金幣則在螢幕中隨機位置生成一個金幣。如果金幣數量小於3則有20%機率生成一個金幣


玩家每拾取3個金幣，就在螢幕外隨機位置生成一個敵人（生成方式為：從中心開始，隨機選擇一個角度（在0到360度內均勻隨機），然後取此方向的延長線上選擇最近的離視窗邊界至少100像素的點）


敵人碰到玩家會使其消失。玩家消失後敵人會嘗試離開螢幕。這時，在所有敵人離開螢幕後，重新生成玩家
```

這個節點可以理解為整個玩法範例的總場景規則。

## 第三步：在其內部建立 3 個子節點

接下來，在 `場景` 節點內部繼續建立三個節點：

- `玩家`
- `金幣`
- `敵人`

### 節點：玩家

內容填寫為：

```text
繪製一個白色的等腰三角形以表示玩家。其底邊長為24像素，高32像素。

玩家可以透過A/D鍵轉向，角速度為180度每秒。按住W鍵向前移動，速度為300像素每秒。按住S鍵向後移動，速度為100像素每秒。
```

### 節點：金幣

內容填寫為：

```text
形象為黃色圓形，半徑8像素
```

### 節點：敵人

內容填寫為：

```text
形象為一個紅色矩形

每秒速度在100到200之間，朝向玩家移動（如果玩家不存在則向螢幕外移動，方向朝向最近的邊界）

長寬在16像素到40像素之間

其生成時，以上三個數值隨機決定，之後不再改變
```

## 第四步：建立邊關係

在節點建立完成後，繼續建立兩條關係邊。

### 邊：敵人 → 玩家

將 relation 改為：

- `destroys`

內容填寫為：

```text
敵人碰到玩家後，玩家消失
```

### 邊：玩家 → 金幣

將 relation 改為：

- `collects`

內容填寫為：

```text
玩家碰到金幣時，將其拾起
```

到這裡為止，你已經完成了一套最小但完整的設計結構：

- 有總場景規則
- 有物件節點
- 有物件間關係

這已經足夠拿來作為一次 agent 實作測試。

## 第五步：讓 programmer 開始實作

當上面的節點和邊都完成後，切換到 **programmer**，然後對它說：

```text
你好，我在試用這個軟體。我提供了一個範例專案，請將其實作
```

這一步的目的，是讓 programmer 基於你剛剛建立的 Graph 結構，嘗試把這個範例專案落地為程式碼。

## 第六步：等待結果

傳送後，等待 programmer 回傳結果。

這一步不一定會瞬間完成，因為它可能需要：

- 閱讀目前 Graph 結構
- 理解節點與邊表達的規則
- 組織程式碼落點
- 逐步寫入專案檔案

所以這裡的重點是：

- 讓它先完成一輪實作
- 觀察它是否能正確理解你給出的設計結構

## 第七步：透過 Execute 編譯和執行

當 programmer 完成後，使用頂部選單中的：

- **Execute**

先進行：

- **Compile Project**

如果編譯成功，再繼續：

- **Run Project**

這樣你就完成了一次完整試用：

- 用 Graph 寫設計
- 用 agent 讀取並實作設計
- 用 Execute 編譯執行結果

這就是本教學的終點。

## 這個使用範例想幫助你驗證什麼

如果這套流程整體跑通，通常就說明：

- 你已經會建立基本專案
- 你已經會用節點和邊表達設計
- programmer 能讀取並利用這套設計結構
- 本機編譯與執行鏈路基本正常

換句話說，如果你能順利完成這個例子，就已經對 ANGEL GUI 的核心工作流有了第一輪完整體驗。
